# 최근 수정 및 배포 기록

Codex와 Claude가 함께 사용하는 인계 문서다. 최신 항목을 맨 위에 추가한다.
작업 시작 시 이 문서와 `git status`를 확인하고, 완료 시 실제 검증 결과와 배포 상태를 갱신한다.

## 2026-11-05 — 프로젝트에 비밀번호를 걸 수 있다

- 요청: 새 프로젝트를 만들 때 비밀번호를 **고를 수 있게** 하고, 이 컴퓨터의 프로젝트를
  열 때 그것을 묻는다. 안 걸고도 만들 수 있어야 한다. **`.mlpx`를 파일 불러오기로 열 때는
  묻지 않는다** — 교사가 제출물을 평가해야 한다.
- 설계: 잠금은 **IndexedDB 레코드에만** 산다(`exportedAt`과 같은 자리). 그래서 네 번째
  조항이 저절로 충족되고 `FORMAT_VERSION`도 안 건드린다.
- 거는 자리: **라우터 가드가 부르는 `stores/project.ts`의 `open()` 하나**다. 프로젝트는
  주소로 열리므로 목록의 클릭 처리기에만 걸면 **주소를 치거나 F5를 누르는 것으로 뚫린다.**
  브라우저로 실제 확인했다 — 잠긴 프로젝트에서 새로 고치니 목록으로 되돌아왔다.
- 통과는 **이 탭의 메모리에만** 둔다. 새로 고치면 다시 묻는다.
- 해시: `hashText`(SHA-256) + 소금. **`crypto.subtle`은 쓰지 않는다** — 자가호스팅이
  http라 보안 컨텍스트가 없고, 이 저장소가 이미 버린 길이다(`hash.ts`).
- **함정 하나를 막았다**: `saveProject`가 레코드를 통째로 쓰므로 `lock`을 다시 실어
  주지 않으면 **자동 저장 한 번에 잠금이 조용히 사라진다.** 보존 줄을 빼고 돌려 검사가
  우는 것까지 확인했다(`storage.spec.ts`).
- 범위: 삭제에는 안 건다(컴퓨터실 정리가 막힌다). 힌트를 선택으로 받는다(비밀번호는
  저장하지 않으므로 잊으면 못 연다). 둘 다 사본 소유자 결정이다.
- 한계: **암호화가 아니다.** IndexedDB는 devtools에서 그대로 보인다. 막는 것은 공용
  PC에서 옆자리 학생이 여는 일이다. 근거는 `open-decisions.md` "프로젝트에 잠금을 걸 수
  있다 — 파일에는 안 들어간다".
- 검증: `npm run ci` 전체 통과(167개 테스트 파일, 3,346개 통과·2개 제외). 검사 셋을 더했다 —
  `lock.spec.ts`(셈), `project-password.spec.ts`(열기 길목 배선), `storage.spec.ts`(보존과
  문서 비침투).
- 화면 확인: 개발 서버에서 만들기 → 잠김 표시 → 틀린 비밀번호 → 맞는 비밀번호 →
  새로 고침까지 한 바퀴 돌렸다. 콘솔 오류 없음.
- 배포: 완료했다. 결과는 아래와 같다.

## 2026-11-05 — 시간에 쫓기던 검사 둘을 판별력으로 바꿨다

- 계기: 위 배포가 **고친 것과 무관한 이유로** 막혔다. `bench-rules.spec.ts`의
  `전부 한 번에 잰 것이 일감 하나보다 길다`가 **126 대 128**로 뒤집혔다.
- **그 단정은 애초에 참이 아니었다.** 일감 하나를 재는 갈래는 **일감마다 새 워커**라
  차가운 시작을 물고, 전부 한 번에 재는 갈래는 **한 워커에서 이어 돌아 따뜻하다** —
  `tools/workloads.ts`의 `measureCalibrationSet` 주석이 그 비대칭을 이미 적어 두었는데
  검사가 그것과 어긋난 단정을 들고 있었다.
- 바꾼 것: 하나와 전부를 견주는 대신 **일감들의 합**과 견준다. 전부 지나갔으면 합에
  가깝고 하나만 지나갔으면 그 절반 아래로 떨어지므로, 두 경우의 간격이 **배수**다.
  일부러 "하나만 재게" 망가뜨려 **32 대 55**로 우는 것을 확인했다.
- `locales.spec.ts`의 `동작의 이름에 순우리말을 쓰지 않는다`는 짝마다 `expect`를 불러
  **문구 942개 × 낱말 73개 = 68,766번**이었고, 그 호출 비용만으로 5초 제한에 닿았다
  (느린 기기에서 6.2초·10.5초). 어긋난 것을 모아 **한 번만** 단정하도록 바꿨다 —
  `골라`를 심어 여전히 무는 것과, **6,222ms → 17ms**를 확인했다.
- 잡는 범위는 둘 다 그대로다. 로케일 쪽은 오히려 **어긋난 것을 전부** 보여 준다 —
  예전에는 첫 번째에서 멈췄다.
- 검증: `npm run ci` 전체 통과(167개 테스트 파일, 3,346개 통과·2개 제외).

## 2026-11-03 — 내장 포트폴리오 양식에 `결론(반성 및 제언)` 문항 추가

- 요청: 내장 양식에 아홉 번째 문항 `결론(반성 및 제언)`을 더한다. 생활기록부에 기재될 수
  있으므로 자세히 쓰게 한다.
- 변경: `public/portfolio/default.ko.md`와 `default.en.md`에 `{#conclusion}` 문항을 더했다.
  **양식은 코드가 아니라 파일이다**(`mlpx-spec.md` §8.7) — 문항을 늘리는 데 코드 수정이 없다.
- 쌍: 두 파일의 문항 id와 순서가 같은 것을 확인했다. **id가 어긋나면 한 언어로 쓴 답이
  다른 언어 양식에서 떨어져 나간다**(§8.2).
- 겹침: 8번 `문제 해결 과정과 성찰`과 묻는 것이 일부 겹친다(둘 다 되돌아보기다). 그래도
  나눈 이유는 **쓰이는 자리가 다르기 때문이다** — 8번은 과정의 기록이고, 9번은 프로젝트
  전체를 매듭짓는 한 편의 글이다. 안내문이 그 차이를 말한다(8번은 "어려웠던 문제와 해결
  과정", 9번은 "결과가 무엇을 뜻하는지·무엇을 더 탐구하고 싶은지").
- 문구: 요청한 말("생기부에 기재될 예정이므로 반드시 자세히 작성")을 양식의 말투에 맞춰
  문장으로 폈고, **`생기부`는 `학교생활기록부`로 적었다**(`docs/terms.md` — 줄임말을 쓰지
  않는다). 영어 쌍은 `생기부`를 그대로 옮기지 않고 "학교 기록에 인용될 수 있다"로 적었다 —
  제도가 한국의 것이라 그대로 번역하면 밖에서 뜻이 없다.
- 검증: `npm run ci` 전체 통과(165개 테스트 파일, 3,325개 통과·2개 제외). 내장 양식을 훑는

### 남은 일 — 검사 하나가 시간에 쫓긴다

- `104adf7`(문서만 바꾼 커밋)에서 CI가 빨개졌다. **이 변경 때문이 아니다** —
  `locales.spec.ts`의 `동작의 이름에 순우리말을 쓰지 않는다`가 5초 제한에서 시간 초과했고,
  그 검사는 **로케일 JSON만 읽는다**(이번에 바꾼 것은 `public/portfolio/`의 `.md` 둘이고,
  그쪽을 읽는 바로 옆 검사는 통과한다).
- 잰 것: 로케일 문구 942개 × 걷어낸 낱말 73개 = **`expect` 호출 68,766번**. 단독으로 돌리면
  통과하고(측정 3회), 전체 묶음이 병렬로 돌 때 6.2초·10.5초로 넘쳤다. **고질이지 이번
  회귀가 아니다.**
- 고치는 길: 짝마다 `expect`를 부르지 말고 **어긋난 것을 모아 한 번만 단정**하면 호출이
  6만 8천 번에서 한 번으로 준다. 잡는 범위는 그대로다. **손대지 않았다** — 검사를 고치는
  것은 감사 국면의 일이고 그 국면은 사용자가 연다(CLAUDE.md §4).
